# Журнал проблем и затруднений

## 2026-10-12 21:17 +03:00 — Ограничение доступности модели прервало ход агента

- **Задача / контекст:** Перевод ключа JWT на Base64 и проверка конфигурации авторизации.
- **Что произошло:** По сообщению координатора ход завершился ошибкой «Selected model is at capacity».
- **Решение:** Возобновлена та же задача тем же агентом; перечитаны сохраненные файлы и продолжен существующий NUnit-процесс. Release build и полный прогон 279 тестов завершились успешно. Новые агенты и изменения harness не потребовались.

## 2026-10-12 19:39 +03:00 — Node/Vite отсутствуют в PATH и получают spawn EPERM в sandbox

- **Задача / контекст:** Сборка React и Vitest для refresh tokens и гонок клиентской сессии.
- **Что произошло:** npm отсутствует в PATH. Локальные Vite/Vitest CLI с bundled Node запускаются, но sandbox блокирует дочерний Windows realpath probe с spawn EPERM.
- **Предпринятые попытки:** npm run build/npm test; затем локальные tsc/Vite/Vitest с добавлением bundled Node в PATH. TypeScript проходит, Vite/Vitest требуют разрешения дочернего процесса.
- **Решение:** Auto-review разрешил запуск имеющихся CLI вне sandbox. Vite build и Vitest завершились успешно; зависимости и production-конфигурация не менялись.
- **Предполагаемая первопричина:** Ограниченный PATH среды и запрет запуска дочернего процесса Vite для Windows realpath.
- **Предлагаемое улучшение:** Подключать bundled Node и разрешать дочерние процессы стандартных build/test CLI в окружении frontend-проверок.

## 2026-10-12 19:25 +03:00 — Windows Event Log маскирует ожидаемую ошибку SQLite в API-тесте

- **Задача / контекст:** Проверка отказа login при ошибке записи AdminSessionRecord в настоящую файловую SQLite.
- **Что произошло:** При намеренно отклоненной вставке тестовый хост попытался записать ошибку в системный журнал Windows. Sandbox отказал в доступе, исключение логгера замаскировало ошибку SQLite и помешало обычному ответу 500.
- **Предпринятые попытки:** Полный NUnit-прогон выявил ошибку в единственном новом тесте отказа записи; остальные 245 проверок прошли.
- **Решение:** Общая TestApplicationFactory отключает только провайдер EventLog; остальные логи и production-настройки сохраняются. Тест проверяет ответ 500 без JWT и отсутствие строки сессии.
- **Предполагаемая первопричина:** Стандартный Windows-хост подключает системный EventLog без доступных тестовому процессу прав записи.
- **Предлагаемое улучшение:** Изолировать системные провайдеры логирования в общей фабрике HTTP-тестов при проверке ошибок.

## 2026-10-12 18:56 +03:00 — Тестовый хост обращается к пользовательским ключам Data Protection

- **Задача / контекст:** Проверка первого и повторного запуска приложения с инициализацией SQLite через WebApplicationFactory.

- **Что произошло:** ASP.NET Core пытался записать ключ Data Protection в пользовательский каталог за пределами workspace; в sandbox возник UnauthorizedAccessException. HTTP-тесты продолжили работу, но в выводе появилась ошибка, не связанная с проверяемой БД.

- **Предпринятые попытки:** Запущен общий набор NUnit-тестов с реальными временными SQLite-файлами; ошибка обнаружена в выводе тестового хоста.

- **Решение:** В общей TestApplicationFactory включен встроенный ephemeral provider Data Protection. Production-конфигурация не меняется.

- **Предполагаемая первопричина:** Стандартный тестовый хост наследует файловое хранилище ключей ASP.NET Core из пользовательского окружения.

- **Предлагаемое улучшение:** Для новых HTTP-тестов использовать общую TestApplicationFactory с временной SQLite и изолированным Data Protection.

## 2026-10-12 18:56 +03:00 — Docker CLI установлен, Linux daemon недоступен

- **Задача / контекст:** Проверка Dockerfile и Compose после добавления создания SQLite при запуске.

- **Что произошло:** docker info не смог подключиться к dockerDesktopLinuxEngine: именованный канал отсутствует. Сборка и запуск образа недоступны; наличие CLI не подтверждает наличие работающего daemon.

- **Предпринятые попытки:** Выполнена проверка docker info перед сборкой контейнера.

- **Решение:** Ограничение сохраняется. Проверяются конфигурация Compose, сборка .NET и запуск тестового хоста; отсутствие проверки образа отмечается в результате.

- **Предполагаемая первопричина:** Linux engine Docker Desktop не запущен либо недоступен в текущей сессии.

- **Предлагаемое улучшение:** Перед задачами с контейнерами проверять доступность daemon и предоставлять работающий Linux engine для проверки AMD64/ARM64.
