## Задачи

- [ ] **[P2] Формировать дату Docker-тега в часовом поясе Europe/Moscow.**

  Место: [.github/workflows/ci.yml](.github/workflows/ci.yml), шаг `Version`, строка 79 на момент ревью.

  Проблема: `git show --date=format:` сохраняет часовой пояс даты коммита; `TZ: Europe/Moscow` не преобразует
  календарный день. Например, коммит в 23:30 UTC получит дату предыдущего дня относительно Москвы.

  Предлагаемая правка: использовать `--date=format-local:` с заданным `TZ: Europe/Moscow`, сохранив формат
  `YYYY.M.D.<github.run_number>`.

  Проверка: взять коммиты с разными часовыми поясами около границы московского дня и проверить дату и итоговый тег.
  Требование к часовому поясу и формату тега закреплено в [AGENTS.md](AGENTS.md), разделе «Структура репозитория и
  сборка».

- [x] **[P2] Игнорировать поздний ответ создания задания из предыдущей сессии.**

  Место: [src/Ytdlp.Ui.Client/src/App.tsx](src/Ytdlp.Ui.Client/src/App.tsx), обработчик `onCreated`, строка 96 на момент
  ревью.

  Проблема: обработчик проверяет только наличие текущего токена. Если запрос создания задержался, прежняя сессия
  получила `401`, а администратор вошел снова и открыл новую форму, старый успешный ответ может закрыть эту форму и
  потерять введенный URL.

  Предлагаемая правка: проверять совпадение текущего токена с токеном исходного запроса, как в обработчике `act`.

  Проверка: задержать ответ создания из прежней сессии, выполнить выход по `401` и повторный вход, открыть новую форму и
  ввести URL. После старого ответа новая форма и ее данные должны сохраниться. Также проверить обычное успешное создание
  в текущей сессии. Правила очистки административного состояния закреплены в [AGENTS.md](AGENTS.md), разделе «Библиотека
  и доступ».

Исправлено на этапе OIDC: useAuth сверяет server UI sessionId до и после запроса, App.onCreated проверяет идентичность
исходной сессии. Регрессия подтверждена в [App.test.tsx](src/Ytdlp.Ui.Client/src/App.test.tsx), тест "does not close or
reset a new URL form after an old successful create response": отложенный create → 401 фонового запроса → новый вход →
новая форма сохраняет URL после старого успешного ответа.
