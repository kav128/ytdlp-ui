# Proposal

## Why

Администратору нужно сохранять отдельную книгу Flibusta в той же публичной библиотеке S3, что и остальные файлы.
Согласован сценарий по ссылке на карточку с результатом FB2, исходным именем файла и необязательным читаемым названием.

## What Changes

- Существующая форма URL автоматически распознает карточку Flibusta `/b/{id}` с разрешенного домена. Для книги
  единственным параметром задания остается URL; поиск, серии, авторские подборки и ссылки скачивания не добавляются.
- Идентичность задания Flibusta определяется ID записи независимо от зеркала. Правила URL-дубликатов для yt-dlp
  сохраняются; повтор, отмена и удаление используют общую очередь и историю.
- Сервер анонимно получает FB2 через clear web с адреса из конфигурации. Адрес загрузки и список принимаемых доменов
  настраиваются отдельно от сохраненных заданий.
- Готовый FB2 принимается напрямую; ZIP должен содержать ровно один FB2, который распаковывается без конвертации.
  Неожиданный формат или поврежденное содержимое завершают задание ошибкой без публикации.
- Результат сохраняет исходное имя файла. Метаданные FB2 дают nullable `title` вида «Автор — Название» для задания
  и публичной библиотеки; каталог отображает `title ?? name`, скачивание сохраняет исходное имя.
- Общие worker, SQLite-очередь, публикация S3 и восстановление разрабатываются в параллельном этапе MVP и являются
  зависимостью интеграции, а не повторной реализацией в этом change.

OPDS остается отдельной будущей проработкой. В это изменение не входят OPDS-клиент, универсальный реестр каталогов,
просмотр каталога, аккаунт Flibusta, Tor, выбор другого формата, конвертация и обложки.

## Capabilities

### New Capabilities

- `flibusta-downloads`: прием ссылки на одну книгу Flibusta, анонимное получение FB2, распаковка, проверка,
  исходное имя и извлечение необязательного названия в общей цепочке обработки.

### Modified Capabilities

- `download-submission`: исключение из сравнения по URL для Flibusta — дубликаты и атомарные команды по ID записи.
- `public-library`: отдельный nullable `title` при сохранении `name`, полноты S3-каталога и имени скачиваемого файла.
- `web-interface`: та же форма URL для книг и роликов, название книги в карточке и `title ?? name` в каталоге.

## Impact

- Backend: `Features/Downloads`, доменная идентичность источника, HTTP-адаптер Flibusta и подготовка FB2;
  без запуска yt-dlp/FFmpeg для книг и без отдельного worker.
- SQLite: миграция идентичности книги, сохраняемого исходного имени и nullable названия конкретной публикации.
  Существующие задания и история должны сохраниться.
- S3/каталог: общая публикация готового артефакта, дополнение полного listing известными названиями своих публикаций.
  Ручные загрузки и внешние объекты остаются доступны без title.
- API/React: существующий `POST /api/downloads` с `{ url }`; в модели файла библиотеки добавляется nullable `title`.
  Маршрут содержимого и `name` сохраняют назначение.
- Проверки: локальный HTTP-источник, файловая SQLite, MinIO, React; отдельная проверка фактического ответа Flibusta.
  При реализации обновляются соответствующие разделы `readme.md`; подготовка этих артефактов не меняет код приложения.
