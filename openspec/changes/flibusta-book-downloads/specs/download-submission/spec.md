# Spec Delta

## MODIFIED Requirements

### Requirement: Дубликаты по нормализованному URL

Приложение ДОЛЖНО (SHALL) сохранять исходную ссылку. Для источников yt-dlp дубликаты определяются по нормализованному URL: удаляются внешние пробелы, нормализуются схема, host и стандартный порт; регистр пути, query-параметры и их порядок сохраняются. Разные ссылки не объединяются по ID ролика. Для Flibusta идентичность определяется ID записи книги независимо от разрешенного зеркала и адреса загрузки из конфигурации.

#### Scenario: Технически эквивалентная ссылка
- **WHEN** URL источника yt-dlp отличается только внешними пробелами, регистром host или стандартным портом
- **THEN** проверка дубликата находит то же задание

#### Scenario: Разные ссылки на один ролик
- **WHEN** ссылки ведут на один ролик, но имеют разные нормализованные URL
- **THEN** приложение не объединяет их автоматически

#### Scenario: Значимые части URL
- **WHEN** ссылки источника yt-dlp отличаются регистром пути, query-параметрами или их порядком
- **THEN** эти различия не удаляются при нормализации

#### Scenario: Одна книга на разных зеркалах
- **WHEN** допустимые карточки Flibusta с разных разрешенных доменов содержат один ID записи
- **THEN** они соответствуют одному логическому заданию
- **AND** исходная ссылка ранее созданного задания сохраняется

#### Scenario: Разные записи книги
- **WHEN** карточки Flibusta имеют разные ID, даже если название и автор совпадают
- **THEN** они считаются разными источниками и допускают отдельные задания

### Requirement: Отклонение зарегистрированного URL

Приложение ДОЛЖНО (SHALL) отклонять создание по уже зарегистрированной идентичности источника с понятным сообщением, кроме подтвержденного удаления готового результата. Для yt-dlp сравнивается нормализованный URL, для Flibusta — ID записи книги. Ошибка или отмена прежнего задания допускают явный ручной повтор, а не новую логическую загрузку.

#### Scenario: Действующее или завершенное задание
- **WHEN** источник принадлежит ожидающему, активному, отменяемому заданию или завершенному заданию с доступным файлом
- **THEN** повторное создание отклоняется как дубликат с указанием существующего задания

#### Scenario: Неудачная или отмененная попытка
- **WHEN** источник принадлежит заданию в `Failed` или `Canceled`
- **THEN** создание отклоняется как дубликат
- **AND** администратор может использовать действие повтора существующего задания

### Requirement: Повтор после удаления результата

Приложение ДОЛЖНО (SHALL) при повторной отправке источника удаленного результата создавать новую попытку старого задания со скачивания. Для Flibusta источник находится по ID записи независимо от зеркала; для yt-dlp — по нормализованному URL. Кнопка повтора использует тот же механизм; ID загрузки, исходный URL и прежняя история сохраняются.

#### Scenario: Повторная отправка URL
- **WHEN** администратор отправляет URL источника задания в `Deleted`
- **THEN** прежнее задание получает новую попытку с начала скачивания
- **AND** новая логическая загрузка не создается

#### Scenario: Готовый результат удален вне приложения
- **WHEN** при административном создании или повторе подтверждено отсутствие прежнего результата в S3
- **THEN** задание фиксирует удаление и допускает новую попытку с прежним ID

#### Scenario: Хранилище не подтвердило отсутствие
- **WHEN** проверка результата завершилась отказом доступа, сетевой ошибкой, timeout или отсутствием bucket
- **THEN** результат не считается удаленным и новое скачивание по этому основанию не запускается

#### Scenario: Удаленная книга по ссылке другого зеркала
- **WHEN** администратор отправляет допустимую карточку того же ID Flibusta с другого зеркала после подтвержденного удаления результата
- **THEN** создается новая попытка существующего задания
- **AND** исходная ссылка и история не заменяются присланной ссылкой

### Requirement: Атомарная постановка попытки

Приложение ДОЛЖНО (SHALL) исключать создание двух логических загрузок по одной идентичности источника и двух активных попыток одной загрузки при одновременных запросах создания и повтора. Идентичность yt-dlp определяется нормализованным URL, идентичность Flibusta — ID записи книги.

#### Scenario: Одновременное создание
- **WHEN** два запроса одновременно создают задание по одному нормализованному URL источника yt-dlp
- **THEN** существует только одна логическая загрузка и не более одной активной попытки

#### Scenario: Одновременный повтор удаленного результата
- **WHEN** форма создания и кнопка повтора одновременно обращаются к удаленному заданию
- **THEN** принимается не более одной новой попытки
- **AND** ID задания и история сохраняются

#### Scenario: Одновременное создание книги через зеркала
- **WHEN** два запроса одновременно отправляют карточки одного ID Flibusta с разных разрешенных доменов
- **THEN** сохраняется одно логическое задание с не более чем одной активной попыткой
- **AND** второй запрос получает результат проверки дубликата
