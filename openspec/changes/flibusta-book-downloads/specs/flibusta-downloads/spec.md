# Spec Delta

## Purpose

Определяет скачивание одной книги Flibusta по ссылке на карточку, подготовку FB2 и публикацию в общей библиотеке с исходным именем и необязательным читаемым названием.

## ADDED Requirements

### Requirement: Карточка одной книги

Приложение ДОЛЖНО (SHALL) распознавать Flibusta по HTTP(S)-ссылке на карточку `/b/{id}` с домена из конфигурации. ID обозначает одну запись библиотеки. Ссылки чтения, скачивания, поиска, автора и серии не принимаются как источник задания Flibusta.

#### Scenario: Ссылка на карточку
- **WHEN** администратор отправляет карточку `/b/123` с разрешенного домена
- **THEN** источник распознается как Flibusta с ID записи `123`
- **AND** создается задание одной книги по общим правилам создания и поиска дубликатов

#### Scenario: Ссылка другого вида
- **WHEN** ссылка разрешенного домена имеет вид `/b/123/fb2`, `/b/123/epub`, `/b/123/read`, страницы автора или поиска
- **THEN** создание отклоняется с понятной ошибкой о необходимости ссылки на карточку
- **AND** ссылка не передается обработчику yt-dlp вместо Flibusta

#### Scenario: Неразрешенный домен
- **WHEN** URL пытаются использовать как источник Flibusta с доменом вне разрешенного списка
- **THEN** этот домен не используется для получения книги обработчиком Flibusta

### Requirement: Настраиваемый анонимный доступ

Приложение ДОЛЖНО (SHALL) получать книгу анонимно через clear web с базового адреса Flibusta из серверной конфигурации. Список доменов принимаемых карточек настраивается отдельно; домен вставленной ссылки не определяет адрес загрузки. Аккаунт Flibusta и Tor для этого сценария не используются.

#### Scenario: Карточка разрешенного зеркала
- **WHEN** карточка пришла с разрешенного зеркала, отличного от настроенного адреса загрузки
- **THEN** книга запрашивается с настроенного адреса по извлеченному ID
- **AND** учетные данные администратора приложения не передаются Flibusta

#### Scenario: Смена адреса загрузки
- **WHEN** оператор меняет базовый адрес Flibusta, сохраняя конфигурацию допустимой
- **THEN** существующее задание сохраняет идентичность и историю
- **AND** следующая попытка получения использует новый адрес

### Requirement: Только FB2 без конвертации

Приложение ДОЛЖНО (SHALL) получать для указанной записи FB2 и сохранять его содержимое без конвертации. Наличие у записи другого формата не разрешает заменять FB2 на EPUB, PDF или иной формат.

#### Scenario: FB2 доступен
- **WHEN** источник возвращает FB2 или ZIP с FB2 указанной записи
- **THEN** результатом подготовки является один файл `.fb2`
- **AND** содержимое книги не преобразуется в другой формат

#### Scenario: FB2 недоступен
- **WHEN** для записи не удается получить FB2, даже если доступен другой формат
- **THEN** попытка завершается ошибкой
- **AND** другой формат не публикуется как результат задания

### Requirement: Однозначная распаковка и проверка

Приложение ДОЛЖНО (SHALL) принимать готовый FB2 или ZIP с ровно одним обычным файлом `.fb2`. Остальные файлы ZIP игнорируются. Подготовка проверяет содержимое FB2; поврежденный архив, некорректный FB2, отсутствие или несколько файлов FB2 завершают попытку ошибкой без публикации.

#### Scenario: Один FB2 в архиве
- **WHEN** ZIP содержит один FB2 и дополнительные файлы другого типа
- **THEN** подготавливается только этот FB2
- **AND** дополнительные файлы в S3 не публикуются

#### Scenario: Готовый FB2
- **WHEN** источник возвращает корректный FB2 без ZIP
- **THEN** он проходит проверку и подготавливается без изменения содержимого

#### Scenario: Неоднозначный или поврежденный ответ
- **WHEN** ответ содержит поврежденный ZIP, ноль или несколько FB2 либо некорректное содержимое FB2
- **THEN** задание получает `Failed` с понятной причиной
- **AND** результат в S3 не создается

#### Scenario: Имя вложения содержит путь
- **WHEN** ZIP содержит путь к вложению, который мог бы выйти из рабочего каталога задания
- **THEN** подготовка не записывает файл по этому пути
- **AND** никакие файлы вне рабочего каталога задания не изменяются

### Requirement: Сохранение исходного имени

Приложение ДОЛЖНО (SHALL) сохранять имя FB2 из ZIP, а для готового FB2 — имя, сообщенное источником. Имя не заменяется названием из метаданных книги. Одинаковые имена разных публикаций не приводят к перезаписи существующего результата.

#### Scenario: Имя отличается от названия книги
- **WHEN** архив содержит `original_123.fb2`, а метаданные задают другое название
- **THEN** файл библиотеки имеет `name=original_123.fb2`
- **AND** посетитель скачивает файл под этим именем

#### Scenario: Совпадающие имена
- **WHEN** разные записи Flibusta дают FB2 с одинаковым именем
- **THEN** публикации имеют разные идентификаторы файлов и не перезаписывают друг друга
- **AND** имя каждого скачиваемого файла сохраняется

### Requirement: Необязательное название из FB2

Приложение ДОЛЖНО (SHALL) извлекать название и авторов из метаданных FB2 для nullable `title` задания и публикации. При наличии названия и автора используется «Автор — Название»; при наличии только названия — название. Отсутствующее или пустое название дает `title=null` и само по себе не делает корректный FB2 ошибочным.

#### Scenario: Полные метаданные
- **WHEN** FB2 содержит название и автора
- **THEN** задание и его публикация получают читаемый `title`
- **AND** исходное имя и байты FB2 не меняются

#### Scenario: Метаданных названия нет
- **WHEN** корректный FB2 не содержит непустого названия
- **THEN** книга может быть опубликована с `title=null`
- **AND** имя файла не записывается в `title` вместо отсутствующих метаданных

### Requirement: Общая цепочка выполнения

Приложение ДОЛЖНО (SHALL) выполнять книгу в общей последовательной очереди: `Downloading`, `Preparing`, `Uploading`, `CleaningUp`. Для книги подготовка означает распаковку и проверку FB2. История, повтор, отмена, удаление и восстановление подчиняются общему жизненному циклу загрузки.

#### Scenario: Совместная очередь книг и роликов
- **WHEN** книга и ролик ожидают выполнения
- **THEN** они используют общую очередь с одним одновременно выполняющимся заданием
- **AND** для подготовки книги не запускаются медиапроцессы

#### Scenario: Ошибка отправки
- **WHEN** отправка в S3 не удалась, но подготовленный FB2 сохранен и пригоден
- **THEN** ручной повтор использует этот FB2 без повторного получения и распаковки книги

#### Scenario: Непригодный входной файл
- **WHEN** проверка установила, что скачанное содержимое непригодно для подготовки
- **THEN** попытка завершается ошибкой, а история отражает непригодность входного файла
- **AND** ручной повтор не переиспользует его как пригодный результат скачивания

### Requirement: Отказы источника без ложного результата

Приложение ДОЛЖНО (SHALL) завершать попытку понятной ошибкой при недоступности источника, отказе доступа или неожиданном формате ответа. HTML-страница, включая страницу входа или блокировки с HTTP 200, не считается книгой и не публикуется в S3.

#### Scenario: HTML вместо книги
- **WHEN** источник возвращает HTTP 200 с HTML-страницей вместо FB2 или ZIP
- **THEN** задание получает `Failed` с ошибкой формата источника
- **AND** HTML не появляется в публичной библиотеке

#### Scenario: Источник недоступен
- **WHEN** получение завершается сетевой ошибкой, timeout или неуспешным HTTP-статусом
- **THEN** ошибка сохраняется в истории попытки
- **AND** повтор остается явным административным действием
