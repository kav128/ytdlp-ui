## Context

Состав каталога определяется listing S3. API вычисляет `name` и имя скачивания из ключа объекта. Ручной файл или внешний объект может не иметь связанного задания в PostgreSQL.

## Goals / Non-Goals

- Хранить необязательный заголовок для любого файла каталога и сохранить существующие идентификаторы и ссылки.
- Переименование ключа, изменение содержимого и изменение названия задания находятся за рамками этой функции.

## Decisions

- `PUT /api/library/{id}/title` принимает `{ "title": "…" }` или `{ "title": null }`. Действуют существующие правила Admin и CSRF. Сервер убирает пробелы по краям, трактует пустое значение как сброс и отклоняет заголовок длиннее 255 кодовых единиц UTF-16 или с управляющими символами.
- Отдельная таблица PostgreSQL хранит заголовок по ключу объекта, ETag и времени изменения с точностью до секунды, доступной и в HEAD, и в listing. Команда проверяет наличие объекта через HEAD, затем выполняет атомарный upsert или удаление записи. Каталог присоединяет сохраненные заголовки одним запросом к БД; миграция создает пустую таблицу.
- API списка возвращает `name` и `title`. Ссылка, содержимое и имя вложения вычисляются по прежним правилам. Интерфейс показывает `title ?? name`, а в диалоге отдельно выводит исходное имя.

## Risks / Trade-offs

При внешней замене запись видна только при совпадении ключа, ETag и времени. Если хранилище возвращает те же значения для двух объектов, каталог считает их одной версией. Скрытые записи отсутствующих объектов не участвуют в выдаче.
