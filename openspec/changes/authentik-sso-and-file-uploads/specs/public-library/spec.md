# Spec Delta

## MODIFIED Requirements

### Requirement: Хранилище является источником каталога

Приложение ДОЛЖНО (SHALL) показывать все файлы настроенного bucket: результаты скачивания по URL, файлы, отправленные администратором через приложение, и файлы, добавленные извне. Состав библиотеки определяется S3, а не наличием заданий в PostgreSQL.

#### Scenario: Файл добавлен извне

- **WHEN** в bucket находится файл без связанного задания в БД
- **THEN** файл присутствует в каталоге и доступен для публичного скачивания

#### Scenario: Файл отправлен через приложение

- **WHEN** ручная отправка администратора успешно опубликовала объект
- **THEN** объект включается в тот же каталог без требования создать задание скачивания

### Requirement: Потоковая передача через бэкенд

Приложение ДОЛЖНО (SHALL) передавать любой файл библиотеки посетителю потоком через бэкенд без загрузки всего файла в память и без перенаправления на прямой URL MinIO. Файл выдается как скачивание с безопасным именем и сохранением содержимого.

#### Scenario: Скачивание файла

- **WHEN** посетитель запускает скачивание существующего файла
- **THEN** бэкенд передает содержимое потоком как скачиваемый файл
- **AND** не возвращает перенаправление на MinIO и не буферизует весь файл в памяти

#### Scenario: Скачивание произвольного содержимого

- **WHEN** посетитель скачивает отправленный администратором документ, архив или другой файл
- **THEN** ответ содержит исходные байты и имя для сохранения на устройство
- **AND** содержимое не исполняется как страница приложения

### Requirement: Административное удаление объектов

Приложение ДОЛЖНО (SHALL) позволять администратору удалять файлы S3 из того же каталога, включая отправленные через приложение и добавленные извне файлы без задания. После подтвержденного удаления файл исчезает из каталога; история связанного задания при его наличии сохраняется.

#### Scenario: Удаление внешнего файла

- **WHEN** администратор удаляет файл, добавленный вне приложения
- **THEN** отсутствие задания в PostgreSQL не препятствует удалению объекта

#### Scenario: Удаление собственного результата

- **WHEN** администратор удаляет готовый файл приложения, связанный с заданием скачивания
- **THEN** после подтверждения отсутствия объекта файл исчезает из каталога
- **AND** связанное задание фиксирует `Deleted` и сохраняет историю для повтора

#### Scenario: Удаление отправленного файла

- **WHEN** администратор удаляет файл, отправленный через форму загрузки
- **THEN** объект удаляется по общим правилам каталога
- **AND** отсутствие задания yt-dlp не является ошибкой
