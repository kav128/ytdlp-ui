# Proposal

## Why

На сервере уже работает Authentik, поэтому отдельные учетные данные и выдача токенов внутри приложения усложняют управление доступом. Библиотека также должна принимать локальные файлы администратора и предоставлять их посетителям вместе с результатами скачивания по URL.

## What Changes

- **BREAKING**: заменить локальный логин/пароль на SSO по OIDC через существующий Authentik. Права администратора получают участники настраиваемой группы Authentik; успешный вход без этой группы не открывает управление.
- **BREAKING**: заменить собственные Bearer JWT, refresh API и `sessionStorage` серверной сессией с HttpOnly cookie. Сохранить абсолютный срок локальной сессии 12 часов, проверку входа после загрузки UI и отзыв при выходе; добавить защиту изменяющих запросов от CSRF.
- Добавить отправку произвольного локального файла администратором в тот же S3 bucket. После подтвержденной публикации файл появляется в общем каталоге и скачивается анонимным посетителем через бэкенд.
- На единой странице заменить форму пароля кнопкой SSO и добавить отдельное действие загрузки локального файла с отображением состояния отправки.
- Сохранить публичное чтение, каталог всех объектов bucket и существующие правила заданий скачивания по URL. Ручная отправка файла не создает фиктивное задание yt-dlp.
- Не включать установку или администрирование Authentik, глобальный выход из всех SSO-приложений, прямую отправку браузера в MinIO, пакетную/возобновляемую загрузку файлов, редактирование файлов и новые роли. Прежние ограничения MVP на плейлисты, эфиры, перекодирование и телеметрию остаются.

## Capabilities

### New Capabilities

- `file-uploads`: административная отправка локального файла, подтверждение публикации, сохранение содержимого и имени, обработка ошибок и совпадающих имен.

### Modified Capabilities

- `administrator-access`: OIDC/Authentik, проверка группы, серверная cookie-сессия, CSRF, отказ от локальных паролей и токенов приложения.
- `public-library`: публичное чтение и административное удаление файлов, отправленных через приложение без задания скачивания.
- `web-interface`: вход через SSO и форма отправки локального файла в существующем каталоге.
- `container-delivery`: конфигурация OIDC и сохранение ключей Data Protection для сессий при замене контейнера.

## Impact

- Бэкенд: `Features/Auth`, `Features/Library`, `Infrastructure/Authentication`, новый адаптер S3 в `Infrastructure/Storage`, модель сессий SQLite и новая EF-миграция. Существующие миграции и данные загрузок сохраняются.
- API: изменить контракт `/api/auth/login`, удалить `/api/auth/refresh`, добавить OIDC callback, выдачу CSRF-токена и `POST /api/library/uploads`; оставить публичные маршруты каталога и скачивания.
- React: `useAuth`, API-клиент, `App`, элементы входа и отправки файла, ресурсы EN/RU и тесты. OIDC tokens и client secret во фронтенд не передаются.
- Конфигурация: параметры провайдера Authentik, группы и Data Protection вместо `Admin`/`Jwt`; обновление Docker/Compose, тестовой фабрики, readme и общего технического проекта при реализации.
- Зависимости: OIDC middleware и официальный `AWSSDK.S3` через CPM, Testcontainers только в интеграционных тестах. Проверки используют изолированные OIDC/MinIO, а не пользовательские сервисы.
- На первом запуске после перехода прежние локальные сессии становятся недействительными; требуется вход через Authentik. Реальные OIDC и S3 пока отсутствуют в реализации, поэтому изменение включает необходимую интеграцию публичной библиотеки с MinIO.
