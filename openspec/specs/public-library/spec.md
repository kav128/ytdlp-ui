# Публичная библиотека

## Purpose

Определяет полный каталог объектов S3, публичное потоковое скачивание, редактирование заголовков и административное удаление с сохранением истории собственных загрузок.

## Requirements

### Requirement: Хранилище является источником каталога

Приложение ДОЛЖНО (SHALL) показывать все файлы настроенного bucket: результаты скачивания по URL, файлы, отправленные администратором через приложение, и файлы, добавленные извне. Состав библиотеки определяется S3, а не наличием заданий в PostgreSQL.

#### Scenario: Файл добавлен извне

- **WHEN** в bucket находится файл без связанного задания в БД
- **THEN** файл присутствует в каталоге и доступен для публичного скачивания

#### Scenario: Файл отправлен через приложение

- **WHEN** ручная отправка администратора успешно опубликовала объект
- **THEN** объект включается в тот же каталог без требования создать задание скачивания

### Requirement: Полный плоский список

Приложение ДОЛЖНО (SHALL) собирать все страницы ответа S3 и возвращать каталог целиком как плоский список с названием, размером, датой изменения и действием скачивания. Навигации по папкам, поиска, пользовательской пагинации и кнопки «Показать еще» в MVP нет.

#### Scenario: Несколько страниц S3

- **WHEN** listing хранилища содержит несколько страниц
- **THEN** API и UI предоставляют файлы со всех страниц без дополнительных действий посетителя

#### Scenario: Вложенные ключи

- **WHEN** ключи объектов содержат вложенные префиксы
- **THEN** файлы отображаются в общем плоском списке без переходов по папкам

### Requirement: Публичное чтение и защищенные изменения

Приложение ДОЛЖНО (SHALL) использовать bucket с публичным чтением, а запись и удаление выполнять только авторизованными действиями. Параметры подключения и учетные данные MinIO задаются конфигурацией бэкенда; используется официальный `AWSSDK.S3`.

#### Scenario: Доступ посетителя

- **WHEN** анонимный посетитель читает каталог или файл через приложение
- **THEN** чтение доступно без административной сессии
- **AND** административная запись и удаление ему недоступны

### Requirement: Потоковая передача через бэкенд

Приложение ДОЛЖНО (SHALL) передавать любой файл библиотеки посетителю потоком через бэкенд без загрузки всего файла в память и без перенаправления на прямой URL MinIO. Файл выдается как скачивание с безопасным именем и сохранением содержимого.

#### Scenario: Скачивание файла

- **WHEN** посетитель запускает скачивание существующего файла
- **THEN** бэкенд передает содержимое потоком как скачиваемый файл
- **AND** не возвращает перенаправление на MinIO и не буферизует весь файл в памяти

#### Scenario: Скачивание произвольного содержимого

- **WHEN** посетитель скачивает отправленный администратором документ, архив или другой файл
- **THEN** ответ содержит исходные байты и имя для сохранения на устройство
- **AND** содержимое не исполняется как страница приложения

### Requirement: Административное удаление объектов

Приложение ДОЛЖНО (SHALL) позволять администратору удалять файлы S3 из того же каталога, включая отправленные через приложение и добавленные извне файлы без задания. После подтвержденного удаления файл исчезает из каталога; история связанного задания при его наличии сохраняется.

#### Scenario: Удаление внешнего файла

- **WHEN** администратор удаляет файл, добавленный вне приложения
- **THEN** отсутствие задания в PostgreSQL не препятствует удалению объекта

#### Scenario: Удаление собственного результата

- **WHEN** администратор удаляет готовый файл приложения, связанный с заданием скачивания
- **THEN** после подтверждения отсутствия объекта файл исчезает из каталога
- **AND** связанное задание фиксирует `Deleted` и сохраняет историю для повтора

#### Scenario: Удаление отправленного файла

- **WHEN** администратор удаляет файл, отправленный через форму загрузки
- **THEN** объект удаляется по общим правилам каталога
- **AND** отсутствие задания yt-dlp не является ошибкой

### Requirement: Подтверждение отсутствия результата

Приложение ДОЛЖНО (SHALL) считать собственный результат удаленным только после подтверждения отсутствия объекта в существующем bucket. Отказ доступа, недоступность S3 или отсутствие bucket не подтверждают удаление.

#### Scenario: Внешнее удаление

- **WHEN** проверка собственного результата подтверждает `404/NoSuchKey` в существующем bucket
- **THEN** жизненный цикл задания может зафиксировать удаление по общим правилам автомата

#### Scenario: Хранилище недоступно

- **WHEN** проверка завершилась `403`, timeout, сетевой ошибкой или отсутствием bucket
- **THEN** приложение не переводит результат в `Deleted` по этой причине

### Requirement: Отсутствующий файл не запускает загрузку

Приложение ДОЛЖНО (SHALL) при публичном запросе отсутствующего файла возвращать ошибку отсутствия без создания задания или новой попытки. Повтор скачивания источника остается административным действием.

#### Scenario: Публичный GET после удаления

- **WHEN** посетитель запрашивает содержимое отсутствующего объекта
- **THEN** сервер возвращает ошибку отсутствия
- **AND** очередь и история попыток не изменяются

### Requirement: Административное редактирование заголовка файла

Приложение ДОЛЖНО (SHALL) разрешать администратору с действительной сессией и CSRF-токеном задать, изменить или удалить необязательный заголовок любого существующего файла каталога. Заголовок сохраняется между перезапусками. API каталога возвращает его отдельно от исходного имени. Ключ объекта, идентификатор, ссылка, байты и имя скачиваемого файла сохраняются.

#### Scenario: Установка и изменение заголовка

- **WHEN** администратор сохраняет заголовок файла, в том числе файла без связанного задания
- **THEN** публичный каталог возвращает последнее сохраненное значение и прежнее исходное имя
- **AND** публичное скачивание по прежней ссылке возвращает те же байты с прежним именем

#### Scenario: Удаление заголовка

- **WHEN** администратор удаляет заголовок файла
- **THEN** каталог возвращает исходное имя и отсутствие заголовка, а файл остается доступным для скачивания

#### Scenario: Отклонение изменения

- **WHEN** файл отсутствует, запрос не имеет административного доступа или CSRF-токена либо заголовок недопустим
- **THEN** сервер отклоняет запрос без сохранения изменения
