# Доступ администратора

## Purpose

Определяет публичный доступ и защищенные действия единственного администратора, сроки сессии, обновление токенов и выход из приложения.

## Requirements

### Requirement: Публичное чтение и защищенное управление

Сервер ДОЛЖЕН (SHALL) разрешать анонимное чтение каталога и скачивание файлов и требовать действительную административную сессию для создания заданий, чтения их состояний и истории, повтора, отмены и удаления файлов.

#### Scenario: Анонимный посетитель читает библиотеку
- **WHEN** посетитель без токена запрашивает каталог или существующий файл
- **THEN** сервер предоставляет публичные данные или файл без входа

#### Scenario: Административный запрос без входа
- **WHEN** запрос управления или чтения заданий не содержит действительного административного токена
- **THEN** сервер отклоняет запрос независимо от видимости элементов интерфейса
- **AND** данные заданий не передаются посетителю

### Requirement: Единственный администратор из конфигурации

Приложение ДОЛЖНО (SHALL) проверять учетные данные одного администратора из конфигурации бэкенда. Пароль администратора и секреты S3 не должны попадать во фронтенд, JWT или логи; примеры конфигурации используют демонстрационные значения.

#### Scenario: Вход администратора
- **WHEN** пользователь передает правильные настроенные учетные данные
- **THEN** сервер создает административную сессию и возвращает пару access и refresh tokens

#### Scenario: Неверные учетные данные
- **WHEN** пользователь передает неверный логин или пароль
- **THEN** сервер отклоняет вход без создания действующей сессии и без выдачи токенов

### Requirement: Bearer JWT собственного API

Сервер ДОЛЖЕН (SHALL) принимать access token только в `Authorization: Bearer <token>` и проверять подпись, разрешенный алгоритм HS256, issuer, audience, срок, идентичность и активность административной сессии. Клиент передает токен только собственному API.

#### Scenario: Недействительный токен
- **WHEN** подпись, алгоритм, issuer, audience, срок или связанная сессия не проходят проверку
- **THEN** административный запрос отклоняется

#### Scenario: Токен вне заголовка
- **WHEN** токен передан только в cookie или query-параметре
- **THEN** сервер не считает запрос авторизованным

#### Scenario: Скачивание и сторонние адреса
- **WHEN** клиент формирует публичную ссылку скачивания или обращается к стороннему адресу
- **THEN** JWT не включается в ссылку и не отправляется стороннему серверу

### Requirement: Проверка ключа подписи при запуске

Приложение ДОЛЖНО (SHALL) получать ключ HS256 из конфигурации бэкенда в Base64 с минимум 32 декодированными байтами и отклонять запуск при отсутствующем, пустом, некорректном или коротком ключе. Ошибка не должна содержать секрет.

#### Scenario: Непригодный ключ
- **WHEN** конфигурация не содержит корректного Base64-ключа длиной минимум 256 бит
- **THEN** запуск прерывается с сообщением конфигурации без значения ключа

### Requirement: Сроки access token и сессии

Сервер ДОЛЖЕН (SHALL) выдавать access token на 5 минут, ограничивая его абсолютным сроком сессии 12 часов от входа. Обновление токенов не продлевает абсолютный срок сессии.

#### Scenario: Обновление внутри сессии
- **WHEN** access token истек, но 12-часовая сессия еще действует
- **THEN** действительный refresh token позволяет получить новую пару без ввода пароля

#### Scenario: Граница абсолютного срока
- **WHEN** до истечения сессии осталось меньше 5 минут
- **THEN** новый access token истекает не позднее сессии
- **AND** после истечения сессии refresh отклоняется

### Requirement: Сохраняемые сессии и ротация refresh token

Сервер ДОЛЖЕН (SHALL) сохранять сессии в SQLite, хранить refresh token только как хеш и принимать его только в JSON собственного API. Каждый успешный refresh атомарно заменяет токен; использованный, истекший или отозванный токен отклоняется.

#### Scenario: Конкурентное обновление
- **WHEN** два запроса одновременно используют один действующий refresh token
- **THEN** не более одного запроса получает новую пару
- **AND** прежний refresh token больше не принимается

#### Scenario: Перезапуск приложения
- **WHEN** сервер перезапущен со своей сохраненной БД и прежней конфигурацией подписи
- **THEN** действующая неотозванная сессия остается доступной

#### Scenario: Ошибка сохранения сессии
- **WHEN** сохранение входа или ротации в БД завершилось ошибкой
- **THEN** сервер не выдает неподтвержденную пару токенов

### Requirement: Сессия вкладки браузера

Клиент ДОЛЖЕН (SHALL) хранить access token, его срок и refresh token в `sessionStorage`, сохранять вход при перезагрузке и проверять сессию через API до получения административных данных. Пароль не сохраняется; `localStorage` и функция «Запомнить меня» не используются.

#### Scenario: Перезагрузка с сохраненными токенами
- **WHEN** страница загружается с парой токенов в `sessionStorage`
- **THEN** клиент при необходимости обновляет access token и проверяет сессию на сервере
- **AND** наличие токена само по себе не открывает административные данные

#### Scenario: Истечение access token
- **WHEN** защищенный запрос требует обновления access token
- **THEN** клиент обновляет пару и повторяет запрос не более одного раза
- **AND** параллельные запросы одной сессии используют общее обновление

### Requirement: Выход и отзыв сессии

Сервер ДОЛЖЕН (SHALL) при успешном выходе сохранять отзыв текущей сессии в SQLite. Клиент очищает токены и административные данные после выхода или окончательного `401`; выход и истечение сессии не отменяют фоновые задания.

#### Scenario: Успешный выход
- **WHEN** администратор выходит из текущей сессии
- **THEN** ее access и refresh tokens больше не принимаются, в том числе после рестарта
- **AND** клиент удаляет пару из `sessionStorage` и очищает закрытые данные
- **AND** фоновые задания продолжаются

#### Scenario: Окончательный отказ в авторизации
- **WHEN** обновление не восстановило сессию и запрос окончательно получает `401`
- **THEN** клиент очищает токены и административные данные и прекращает их опрос

#### Scenario: Поздний ответ прежней сессии
- **WHEN** ответ прежнего входа приходит после выхода или нового входа
- **THEN** ответ не восстанавливает старую сессию и не изменяет данные новой

#### Scenario: Ошибка отзыва
- **WHEN** запись отзыва в БД не удалась
- **THEN** сервер не подтверждает успешный отзыв
