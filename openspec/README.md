# Спецификации yt-dlp WebUI

Согласованные требования MVP перенесены из `MVP-SPEC.md` в основные спецификации OpenSpec 2026-11-03. Исходное ТЗ датировано 2026-10-01 и содержит последующие согласованные изменения. Миграция меняет форму хранения документации, сохраняя требования и границы MVP.

## Назначение и источники

Веб-приложение ставит задания на скачивание отдельных роликов, управляет загрузками и предоставляет публичный доступ к файлам S3. Используется схема OpenSpec `spec-driven`.

| Источник | Назначение |
| --- | --- |
| [specs/](specs/) | Согласованный контракт целевого MVP с требованиями и сценариями |

| [changes/](changes/) | Будущие изменения требований, design и задачи конкретных изменений |
| [../AGENTS.md](../AGENTS.md) | Инструкции работы над проектом |

Основные спеки описывают целевой MVP, включая еще не реализованные возможности. Они не являются отчетом о готовности и не заменяют проверку реализации. При миграции не создавались фиктивные завершенные changes или задачи реализации.

## Состояние реализации

По перенесенным документам созданы каркас ASP.NET Core/React, интерфейс с моковыми заданиями и файлами, агрегат `Download`, схема SQLite и миграции. При запуске создается каталог БД, включается WAL и применяются миграции. Авторизация использует SQLite, JWT на 5 минут и refresh с ротацией в пределах 12-часовой сессии; сессии и отзыв переживают перезапуск.

Демонстрационные задания и библиотека остаются в памяти и сбрасываются при перезапуске. Их подключение к постоянному хранилищу, реальные загрузки, MinIO и медиапроцессы относятся к следующим этапам. Подробности и ограничения исходных проверок сохранены в `design.md` и корневом `readme.md`. Миграция документации не подтверждает готовность этих этапов.

## Границы MVP

В MVP отсутствуют плейлисты, прямые эфиры, выбор формата пользователем, перекодирование, телеметрия скачивания через бэкенд, поиск по файлам, навигация по папкам и пользовательская пагинация каталога. Нет ручного переключения языка/темы, отдельной административной страницы, дополнительных сервисов очередей/БД, автоматического удаления временных файлов по сроку или ограничений размера и длительности ролика.

Прямые эфиры, выбор формата, перекодирование и телеметрия требуют отдельной итерации. Возможность запуска yt-dlp в отдельном контейнере — идея для оценки после MVP; для MVP сохраняется дочерний процесс внутри контейнера приложения.

Предложенные polling, порядок сортировки, формат S3-ключей и другие технические defaults находятся в `design.md`. Они не становятся новыми пользовательскими требованиями из-за миграции. Согласованные решения отмечены в его разделе 15.

## Работа с OpenSpec

Из корня репозитория:

```powershell
openspec list --specs
openspec show download-lifecycle --type spec
openspec validate --all --strict --no-interactive
```

Новые изменения оформляются в `changes/` через существующие OpenSpec workflows; технический проект конкретного изменения хранится в его `design.md`. Общие требования обновляются вместе с согласованным изменением. Миграция не создает список задач оставшейся реализации и не запускает ее автоматически.
