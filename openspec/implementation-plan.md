# Реализация полного MVP

План от 2026-11-03. Объем: все основные спецификации `openspec/specs/` с согласованными изменениями
`authentik-sso-and-file-uploads` и `postgresql-persistence`. Задачи changes отслеживаются также в их `tasks.md`; этот план охватывает весь MVP,
включая очередь и настоящие медиапроцессы.

## Порядок работы

- Этапы выполняются последовательно; разработчик начинает следующий только после принятия и коммита предыдущего
  руководителем.
- Разработчик реализует и проверяет этап. Ревьюер независимо проверяет diff и контракт,
  ведет [журнал замечаний](review-log.md). На замечание разработчик отвечает исправлением или конкретным
  контраргументом; спор решает руководитель с указанием доказательств.
- Перед каждым коммитом измененные файлы проходят Reformat через Rider MCP, затем необходимые проверки и финальную
  сверку diff. Сообщение коммита — краткое, на английском, со строчной буквы.
- Каждый коммит содержит результат одного этапа, его проверки, актуальную документацию и записи ревью. Невыполненные
  проверки и остаточные ограничения фиксируются явно; задачи не считаются завершенными по одному наличию кода.
- Применяются `dotnet-repository-structure` и `dotnet-integration-tests`. По новой просьбе пользователя PostgreSQL заменяет
  SQLite с этапа 4; интеграционные тесты используют настоящий PostgreSQL через Testcontainers и миграции. Принятые
  результаты SQLite в этапах 1–3 остаются историческими фактами. Импорт старых данных не нужен, PostgreSQL стартует чистой.
- Синхронизация основных спек с delta выполняется после реализации соответствующих возможностей. Архивация change не
  входит в реализацию и выполняется отдельно по указанию пользователя.

## Исходное окружение

- В этапе 1 pin SDK согласован на 10.0.403 с установленным SDK, CI, Docker и readme.
- Docker Desktop доступен вне ограничений sandbox, работает linux/amd64; Buildx объявляет linux/arm64. Само наличие
  платформы в Buildx не является проверкой запуска.
- Для сборки UI подготовлен официальный Node.js 24.19.0 с npm 11.17.0 в игнорируемом `.tools/`, SHA-256 проверен по
  официальному манифесту; системная установка не меняется.
- Подключен действующий Rider MCP; перед этапным коммитом выполнен Reformat измененных файлов.

## Принятые результаты

### Этап 1

Ревьюер закрыл R1/R2 после независимой проверки. После Rider Reformat: Release build без предупреждений/ошибок, 190
unit-тестов, 89 интеграционных тестов, 3 точечные регрессии UI/ошибок. Изоляция Data Protection подтверждена
захваченными логами Testing. React build и 21 UI-тест прошли; оба режима publish содержат UI, контрольные суммы assets
совпадают с dist.

Образ `ytdlp-ui:stage1` собран и запущен локально на linux/amd64. Проверены React/assets, публичная библиотека, запрет
административного API без входа, непривилегированный пользователь, SQLite volume и сохранение сессии при замене
контейнера. Временные контейнер и volume освобождены. ARM64, MinIO и медиапроцессы на этом этапе не проверялись и
относятся к следующим этапам.

### Этап 2

Ревьюер закрыл R3/R4/R5. Реализованы OIDC/Authen­tik, группа, сохраняемые cookie tickets, CSRF, доверенные Forwarded
Headers и React SSO; первые 12 задач change выполнены. Независимые проверки после Rider Reformat: Release build без
предупреждений, 190 unit-тестов, 100 интеграционных тестов, 3 отдельные проверки сессий, frontend build и 24 UI-теста.
Оба publish содержат UI с совпадающими SHA-256; строгая OpenSpec-валидация прошла 9/9.

Образ `ytdlp-ui:stage2` собран и запущен на linux/amd64. Проверены UI/assets, публичный каталог, запрет административных
запросов без cookie, удаление прежних парольных/refresh endpoints, отклонение внешнего returnUrl, непривилегированный
UID 1654 и сохранение SQLite/key ring при замене контейнера. Фактические права: каталог ключей 755, ключи 600, владелец
UID 1654. Временные ресурсы освобождены. Реальный пользовательский Authentik и ARM64 не проверялись; протокол SSO проверен
изолированным issuer через настоящий middleware.

### Этап 3

Подключен настоящий S3 через AWSSDK.S3: полный каталог, внешние объекты, потоковое скачивание, удаление и ручная отправка
произвольных файлов. Ревьюер независимо подтвердил после Rider Reformat: Release build без предупреждений, 198
unit-тестов, 121 автономный интеграционный тест, 23 Storage-теста на каждом из двух готовых MinIO, frontend build и 28
UI-тестов. Оба publish содержат актуальные assets с совпадающим SHA-256; OpenSpec прошел 9/9. R6 исправлен; контраргумент
по R7 принят с явным ограничением старого MinIO, без заявления об исправлении неподдерживаемого If-Match.

MinIO из исходников не собирается. Для чистого запуска закреплен готовый Bitnami Legacy по digest; отдельно проверен
указанный пользователем локальный `minio/minio:RELEASE.2025-04-22T22-12-26Z`. Собственные публикации используют разные
UUID-ключи; проверено, что позднее удаление прежней публикации не затрагивает новую. Атомарная защита от внешнего writer,
перезаписавшего тот же ключ между HEAD и DELETE, этими версиями MinIO не обеспечивается и не обещается.

Образ `ytdlp-ui:stage3` собран и запущен на linux/amd64. Настоящий Kestrel принял multipart 34 MiB, анонимное скачивание
через бэкенд сохранило SHA-256/Content-Length/attachment; удаление дало 204 и последующий 404. Внешний объект сохранился,
собственный временный файл удален. Подготовка сессии через настоящий ticket store служила только транспортной проверке;
реальный пользовательский Authentik не проверялся. Контейнеры и volumes освобождены. ARM64, медиапроцессы, полные
retry/recovery и визуальная проверка upload на телефоне остаются соответствующим последующим этапам.

### Этап 4

По просьбе пользователя SQLite заменена чистой PostgreSQL без импорта; работают Npgsql, начальная миграция и серверные
tickets. Вместо DemoStore подключены сохраняемые API заданий/истории, нормализация URL, атомарные create/retry/cancel и
claim очереди с общим транзакционным guard. Задания пока ожидают настоящего worker этапа 5; отмена не имитирует очистку.

После Rider Reformat ревьюер независимо подтвердил: Release build без предупреждений, 212 unit-тестов, 148 PostgreSQL
HTTP/persistence-тестов, 27 PostgreSQL+MinIO-тестов, frontend build и 29 UI-тестов. Оба publish содержат актуальные assets
с совпадающими SHA-256 и Npgsql, без SQLite/test dependencies; OpenSpec прошел 10/10. R8 исправлен: длинные URL хранятся
полностью с индексом SHA-256 и точным сравнением строк, без ложного объединения при конфликте hash. Проверены гонки,
сохранение истории/очереди и сессий, а также отсутствие импорта старой БД.

Образ `ytdlp-ui:stage4` собран и запущен на linux/amd64 с отдельными готовыми PostgreSQL 18.6 и MinIO. Проверены чистая
схема, enqueue 201/duplicate 409, прежний ID/история и cookie после замены приложения, logout и отказ прежней cookie
после следующего перезапуска, публичный S3 и 401 для анонимной истории. Контрольный SQLite-файл не изменился; собственные
контейнеры/volumes освобождены. Реальный Authentik не использовался: сессия подготовлена через ticket store. Замеченное
сообщение об отсутствующей GSSAPI библиотеке соответствует документированному необязательному fallback Npgsql; подключение
по паролю прошло, настройка GSS описана в readme. ARM64 и медиапроцессы остаются последующим этапам.

### Этап 5

Подключены настоящий worker сохраняемой очереди, безопасный запуск yt-dlp/FFmpeg/FFprobe/Node, выбор и проверка медиа,
история этапов, артефакты с SHA-256, подтверждение публикации в S3 и локальная очистка. Nullable MediaPlan-миграция
сохраняет прежние задания, историю и tickets. Автономный `.Tests` теперь включает unit/component/process проверки без
Docker; отдельный console ProcessFixture не имеет тестовых зависимостей и не входит в публикацию.

После Rider Reformat ревьюер независимо подтвердил: Release build без предупреждений, 226 автономных проверок, 149
PostgreSQL HTTP/persistence-проверок, 41 PostgreSQL+MinIO-проверку, frontend build и 29 UI-тестов. Оба publish имеют
актуальные assets с совпадающими SHA-256 и не содержат SQLite, тестовых или helper зависимостей. OpenSpec прошел 10/10.
R9/R10 исправлены и независимо перепроверены: точный ALL selector для отдельных дорожек и выбор WebM по кодекам,
с fallback в MKV без перекодирования.

Руководитель отдельно запустил реальные Linux AMD64 инструменты в тестовом overlay: готовые wheels yt-dlp 2026.10.26
с EJS 0.8.0, FFmpeg/FFprobe 6.1.1 и Node 24.19.0. После финального кода MP4 с неизвестными заранее codec/height, DASH с
раздельными дорожками и MKV H264+Opus успешно прошли все четыре этапа. Подтверждены единственная обработка, история
PostgreSQL, разные S3-публикации, публичное чтение через бэкенд с видео 180p и аудио, корректное расширение MKV и пустой
рабочий каталог. Overlay `152deaccefc917e9626ff72b7648b54befbe8c666a8d7f2c8a072c76137fb25b` является тестовой средой;
поставка runtime в основном образе относится к этапу 8. Контейнеры/volumes/network освобождены; реальный Authentik не
использовался. Полная надежность retry/recovery/cancel/delete остается этапу 6.

### Этап 6

Реализованы восстановление прерванных операций перед запуском очереди, проверка пригодности артефактов и подтвержденной
S3-публикации при повторе, сохраненные намерения внешних действий, отмена с подтвержденной остановкой и удаление своего
результата через общую очередь. API собственного удаления возвращает 202 с downloadId; ошибки S3 фиксирует worker в
Failed/ResumeDeleting. Неподтвержденная остановка процесса сохраняет файлы и останавливает приложение и следующие claims,
включая отказ записи ошибки в БД; безопасное продолжение требует завершения всей PID namespace контейнера.

После Rider Reformat ревьюер независимо подтвердил Release build без предупреждений, 232 автономные проверки,
155 PostgreSQL-проверок и 61 PostgreSQL+MinIO-проверку. Проверены ошибки до и после внешних действий/сохранения,
пригодность и утрата артефактов, обе очередности гонки upload/cancel, частичная очистка и барьер остановки процессов.
Frontend build и 31 UI-тест прошли; нестабильная проверка старой upload-сессии R11 исправлена явным ожиданием переходов
сессии без sleeps и потери исходных assertions. Оба publish содержат актуальные UI assets с совпадающими SHA-256,
Npgsql и не содержат тестовых/SQLite-зависимостей; строгая OpenSpec-валидация прошла 10/10.

Отдельный Linux AMD64 reliability probe руководителя на тестовом overlay
`953179624c58edbf4a6fe717dab3ccf8b55a99ec45e0d9b38f8d8912709b9820` подтвердил три настоящих media-сценария,
отмену активной медленной загрузки и выполнение следующей, SIGKILL и восстановление с ручным повтором, сохранение cookie,
ID и истории, queued DELETE202 до Deleted/content404 и новую публикацию после повтора Deleted. Свой work пуст;
временные контейнеры, volumes и сеть освобождены. Реальный Authentik не использовался; полный UI и production runtime
обеих архитектур остаются этапам 7–8.

### Этап 7

Завершены подробная живая история попыток и этапов, локализованные причины продолжения и ошибки, публичное обновление
каталога при фоновой публикации, доступные формы и подтверждения с защитой от устаревших сессий и двойной отправки.
Отдельная nullable ContinuationReasonCode-миграция сохраняет причину повтора после следующего успеха или ошибки;
известные прежние пояснения приложения преобразуются в коды, произвольная диагностика инструментов сохраняется.

После Rider Reformat независимый gate подтвердил frontend build и 48 UI-тестов, Release build без предупреждений,
19 целевых PostgreSQL/MinIO-проверок миграции и истории, оба publish с совпадающими SHA-256 всех трех assets и чистыми
production-зависимостями, строгую OpenSpec-валидацию 10/10. R12 исправлен: видимый выбор файла и пустое состояние
локализованы независимо от языка нативных элементов браузера. Полные непричастные backend-наборы этапа 6 не повторялись;
итоговый полный прогон относится к этапу 8.

На тестовом Linux AMD64 overlay `7e3b802d0c163629f4b3b4a9c434d4c8a29ad3c9a07ea24bbfa9b1c597f973f9` руководитель
проверил обновление прежней PostgreSQL с сохранением cookie, ID заданий, состояний, попыток и этапов. Через браузер
подтверждены отправка произвольного файла 51 Б со сложным именем и анонимное скачивание с совпадающим SHA-256, отправка
пустого файла, новое задание с живой историей Queued→Completed и четырьмя этапами, обновление каталога без Refresh,
локализованная ошибка реального недоступного источника. EN/RU, формы, история и подтверждения доступны на десктопе и
390×844 без горизонтального переполнения. Финальные разрушающие действия в UI не выполнялись; их серверная семантика
проверена предыдущими этапами и UI-регрессиями. Скриншоты сохранены в игнорируемых artifacts/screenshots.

Тёмная тема проверена с реальным prefers-color-scheme:dark; базовые светлые стили просмотрены через отдельный тестовый
proxy, отключающий только dark media block. Автоматическое переключение при настоящем native light preference в IAB
не проверено; production CSS не менялся. Временная вкладка закрыта, viewport сброшен, собственные контейнеры, volumes,
сеть, proxy, конфигурация тестовой cookie и скачанный искусственный файл освобождены. Реальный Authentik и production
runtime обеих архитектур остаются отдельными проверками этапа 8.
