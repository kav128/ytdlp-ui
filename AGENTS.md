# Инструкции для работы над yt-dlp WebUI

- Перед изменениями прочитай [карту требований и границы MVP](openspec/README.md) и относящиеся к задаче спецификации ниже. Они описывают целевой MVP, включая еще не реализованные возможности.
- При проектировании учитывай [технический проект](openspec/design.md). Не считай предложения, технические defaults и открытые вопросы согласованными требованиями.
- Фактический статус, API, команды сборки, тестирования и развертывания смотри в [readme.md](readme.md).

## Работа над изменениями

- Учитывай актуальные указания пользователя. Согласованные изменения требований оформляй через OpenSpec и обновляй спеки вместе с реализацией.
- Общайся с пользователем и веди документацию на русском языке. Для идентификаторов в коде используй английский.
- Приватные поля именуй `_camelCase`, включая `static` и `readonly`.
- Сохраняй изменения пользователя и не затрагивай файлы, не относящиеся к задаче.
- Выбирай простые решения в пределах задачи и MVP. Не добавляй функции и инфраструктуру без необходимости.
- Изменения схемы БД оформляй миграциями.
- При изменении API, сборки, тестирования или развертывания обновляй соответствующие разделы `readme.md`. Отделяй проверенные команды и реализованные возможности от планов.
- Храни здесь инструкции по работе; требования и технические решения поддерживай в OpenSpec по ссылкам выше.

## Проверка изменений

- Выбирай проверки по затронутым сценариям спецификаций; команды запуска бери из `readme.md`.
- После изменения спецификаций выполняй `openspec validate --all --strict --no-interactive`.
- При изменениях интеграции сборки проверяй `dotnet build` и `dotnet publish`, включая наличие готового UI в публикации.
- При изменениях контейнера проверяй сборку и запуск при доступном Docker; учитывай отдельные проверки целевых платформ из `container-delivery`.
- Если Docker или нужная платформа недоступны, явно сообщай о невыполненных проверках. Не выдавай сборку за проверку запуска и не заявляй об успехе незапущенных тестов.
- В итоговом сообщении кратко указывай, что изменено, что проверено и какие проверки остались невыполненными.
